# readme-banner 动效支持设计

日期：2026-11-10
目标技能：`readme-banner`
版本：0.1.0 → 0.2.0

---

## 1. 背景与目标

`readme-banner` 当前只能产出静态图。用户希望它同时能生成**带动效**的 banner，并且**每次生成前先问用户**：生成几张、全静态 / 全动态 / 都有。

本次改造要解决三件事：

1. 让 skill 支持产出带 CSS 动画的 SVG。
2. 在生成前用一个问卷把「数量」和「形态」问清楚，不再由 agent 自行假设。
3. 把踩过的坑固化成可复制的规范，而不是让每个 agent 重新踩一遍。

**不在本次范围内**：GIF / WebP 帧序列导出、PNG 位图动效、主页 `assets/banner.svg` 的视觉重做。

---

## 2. 已验证的技术事实

以下每条都在本机实测确认过（Windows / Node 22.19.0 / Chrome / svgo 4.1.0），是本设计的依据。

### 2.1 GitHub README 会播放 SVG 内的 CSS 动画

GitHub 渲染 README 里的 `<img src="x.svg">` 时，只清洗 `<script>` 和事件处理器，`<style>` 与 `@keyframes` 会保留并真的播放。

⇒ 动效的交付格式定为 **SVG + CSS 动画**，而不是 GIF / WebP：后者要转帧序列，体积通常几百 KB 且不可编辑，而 SVG 仍是 <6KB 的矢量文本。

### 2.2 `npx svgo` 默认配置会毁掉动效产物

默认压缩后：

| 属性 | 结果 |
|---|---|
| 动画本身 | 仍能播（`inlineStyles` 把 `.band` 类内联成 style 属性） |
| `@media (prefers-reduced-motion: reduce)` | **整块被丢弃** |
| `role="img"` | **被删** |

即：动画活着，但**降级规则与无障碍属性同时失效**——而且失效是静默的，压缩后肉眼看不出来。

必须使用专用配置。实测各插件的职责：

| svgo 插件 | 禁用后保住什么 |
|---|---|
| `inlineStyles` | `@media` 块与类选择器（默认把类内联，导致 media 查询失效） |
| `removeUnknownsAndDefaults` | `role="img"` 等未知但合法的属性 |
| `cleanupIds` | `id` / `url(#…)` 引用的稳定性 |
| `minifyStyles` | CSS 原文结构（避免选择器被改写） |

实测：禁用前两项后，产物同时满足 `media=True / role=True / 动画可检出`；四项全禁则多花约 40 字节，换来更稳妥的引用完整性。

### 2.3 无头截帧判定动画：必须用「暂停 + 负延迟」定帧

**`--virtual-time-budget` 不能控制 CSS 动画的时间轴。** 实测同一 SVG 在 120ms / 2600ms / 5000ms 三个预算下截出**同一帧**，只有 800ms / 1600ms 恰好落在另一个相位——说明动画走的是真实时钟，虚拟时间预算对它无效。

正确做法（已校准）：

1. 注入覆盖规则，把动画**暂停**并施加**负延迟**，确定性地定在某个相位：

   ```css
   .band { animation-play-state: paused !important; animation-delay: -3s !important; }
   ```

   必须是 `!important`：原规则里的 `animation` 简写会把 `animation-delay` 重置为 0。

2. 用 Chrome 无头截两帧（相位差 3s），做**像素级差分**。

判据（已用静态图做反向对照校准）：

| 情况 | 差分像素 | 结论 |
|---|---|---|
| 有动效 | 480 / 409600（0.12%） | 动效真在动 |
| 无动效（静态对照） | 0 / 409600 | 正确判定为静态 |

**注意**：只比 PNG 文件哈希**不可靠**——同一画面在不同编码状态下哈希会变。本设计采用像素差分，不用哈希。

### 2.4 base64 内嵌底图 + 动效层可行

B 路径（图像 AI 出底图）叠加 SVG 动效层，做法是把 PNG 以 data URI 内嵌进 SVG 的 `<image>`，再叠手写动效层。

实测：底图 PNG 5.2KB → 合成 SVG 7.5KB，动效正常检出（差分 720 / 409600）。

⚠ 体积代价：base64 会让位图膨胀约 33%，且位图底图无法像矢量那样压到 6KB。B 路径的动效产物**不适用 <6KB 的体积目标**，走 `<50KB` 的宽松线（与 `prompt-image.md` 既有的矢量化产物线一致）。

### 2.5 仓库自身发现的一个既有缺陷

`assets/banner.svg` 的降级规则：

```css
@media (prefers-reduced-motion: reduce){ .an{animation:none !important} }
```

选择器 `.an` **匹配不到任何元素**——实际类名是 `.an-b1` / `.an-b2` / `.an-rule` / `.an-brk`。这条降级规则从未生效。

⇒ 新写出的动效产物必须避免这个错误：**降级选择器要能真正命中被动画的元素**。存量 `assets/banner.svg` 的修复不在本次范围内（它是仓库自身资产，不是 skill 产物），另行处理。

## 3. 已确认的产品决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 动效交付格式 | SVG + CSS 动画 | GitHub 实测会播；体积小、可编辑 |
| 「都有」的语义 | 候选之间混合静态和动态 | 用户明确选择横向对比，而非同一构图出双版本 |
| 图像 AI 路径 | AI 底图 + SVG 动效层叠加 | 保住 AI 的光影质感，同时有动效 |
| 动效强度 | 中等 | 装饰层动 + 轻微文字入场；文字不做持续循环 |

## 4. 生成前问卷

每次生成前用一次 `ask_user` 问完，不拆成多轮。

### 问题 1｜生成几张

- 1 张
- 3 张
- 6 张

### 问题 2｜形态组合

- **全静态** — 所有候选都不带动画
- **全动态** — 所有候选都带动画
- **混合** — 候选之间混合静态与动态（默认项，推荐）

### 混合模式的分配规则

**对位交替分配**：第 1、3、5 张为静态，第 2、4、6 张为动态；每个构图的静态版与动态版**不重复使用同一构图**。

理由：混合的目的是横向对比两种风格路线，每张都是独立构图；同一构图出双版本属于「双版本」语义，已被明确排除。

数量为奇数时，以静态起始、静态收尾（1 张 → 静态；3 张 → 静/动/静；6 张 → 静/动/静/动/静/动）。

配比为等量交替（用户已确认）。若后续用户表达偏向偏好（如「多给两张静态的」），按下一次询问结果调整分配即可，不改默认规则。

### 与既有问卷的关系

原有的「生成方式」选择（A：LLM 写 SVG / B：图像 AI / A+B 各出候选）保留。三问合并为**一个 questionnaire**（`ask_user` 单次调用最多 4 个问题），避免多轮往返。

若用户主动说了数量或形态（如「出 3 张，要动效」），**跳过对应问题**，不重复问。

## 5. 动效规范（强度：中等）

### 5.1 元素分工

| 层 | 是否动 | 做法 |
|---|---|---|
| 装饰层（光带、括号、细线、扫描条） | 动 | 持续循环，周期 5–30s，错峰 delay |
| 文字（标题 / 副标题 / 角标） | **只入场** | 一次性：淡入 + 8px 上移，0.6s，`ease-out` |
| 背景 | 不动 | — |

文字**不做持续循环**：持续动会抢注意力，且干扰阅读。

### 5.2 硬性要求（每个动效产物都必须满足）

1. **首帧即完整可用**——不播动画的阅读器（GitHub 移动端、邮件、部分镜像站）看到的首帧必须是一张完整可用的 banner。每个动画元素同时在**元素属性**上写静态基线（`opacity` / `stroke-opacity`），不依赖 CSS 才可见。
2. **降级规则必须能命中**——`@media (prefers-reduced-motion: reduce)` 里的选择器要指向**真实存在的类名**。参见 §2.5 的反面教材。
3. **CSS `transform` 与 SVG `transform` 属性分离**——CSS 的 `transform` 会覆盖同名的 SVG `transform` 属性。位移动画放在**外层 `<g>`**（用 CSS），旋转 / 缩放放在**内层元素**（用属性），两者复合才生效。
4. **不用 `<foreignObject>` / `xlink:href` / 外部资源引用 / CSS 变量**——GitHub 会 strip 或不解析。
5. 字体栈必须含中文回退：`'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC'`。

### 5.3 动画元素清单（推荐母题）

沿用仓库既有口径：**文字居中排版、不要圆圈图案、装饰用直线型元素**（斜向光带、扫描线、斜纹、直角括号）、动效克制。

可直接复用的 keyframes 模板见 `references/motion.md`。

## 7. 验证方法

每个动效产物生成后必须过这三关，缺一不可：

1. **压缩后仍带降级与无障碍**——用安全配置压一遍，检查 `@media (prefers-reduced-motion)` 与 `role="img"` 是否还在。
2. **动画确实在动**——§2.3 的定帧 + 像素差分，差分像素必须 > 0。
3. **静态对照为 0**——同一套探针跑一张静态图，差分必须是 0。这一步防的是「判定器本身坏了却报通过」。

> 判定器曾因两个原因误报：① 用 PNG 哈希代替像素差分；② `--virtual-time-budget` 当成动画时钟。两者都已修正，但保留静态对照作为常设防线。

## 8. 风险与边界

| 风险 | 缓解 |
|---|---|
| agent 用了 svgo 默认配置，静默丢掉降级规则 | §7 第 1 关强制检查；安全配置写进 `motion.md` |
| agent 声称「有动效」但实际没动 | §7 第 2、3 关，差分像素为准 |
| 降级选择器写错（如 `.an` 那类） | §5.2 硬性要求 2；`motion.md` 给正确写法与反面例子 |
| B 路径 base64 体积膨胀 | B 路径动效产物走 <50KB 宽松线，不适用 6KB 目标 |
| 用户在 README 里用 `file://` 或其他渲染器 | 动效降级为静态首帧，图片仍完整可用 |
| 混合模式下用户对配比有偏好 | 当前等量交替；如需偏向配比，改 §4 的分配规则即可 |

## 9. 明确不做的事

- 不做 GIF / WebP / APNG 帧序列导出。
- 不做 PNG 位图动效（位图本身不动，动的是叠加的矢量层）。
- 不改 `assets/banner.svg` 的视觉设计（其降级选择器缺陷另行处理）。
- 不动 `readme-craft` 的 banner 生成路径——它走的是独立的 `references/banner.md`，本次只改 `readme-banner`。
