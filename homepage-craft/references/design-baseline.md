# design-baseline — 内置设计基线（无 companion 设计 skill 时的兜底）

## 1. 三个风格方向

按项目类型映射（Step 2 已确定类型），用户有明确偏好时偏好优先：

| 方向 | 适合 | 气质 | 关键特征 |
| --- | --- | --- | --- |
| **A 暗色科技** | CLI、devtool、库、基础设施 | 专业、极客、可信赖 | 近黑背景（非纯黑）、单一强调色、等宽字体点缀、细边框分隔、克制的 glow |
| **B 清爽编辑** | 教程、文档型、数据/学术项目 | 冷静、可读、像杂志 | 米白背景、强排版层次（大标题小正文）、衬线 display + 无衬线正文、几乎无色块 |
| **C 大胆产品** | web-app、面向消费者的产品 | 有活力、记忆点强 | 高饱和主色大色块、超大字号标题、不对称布局、克制的渐变（只一处，不超过两个色相） |

**方向 A tokens 示例**（不是唯一解，是"别从零想"的起点）：

```css
:root {
  --bg: #0d1117; --surface: #161b22; --border: #30363d;
  --text: #e6edf3; --text-dim: #8b949e;
  --accent: #58a6ff;            /* 换成项目气质色：绿 #3fb950 / 橙 #d29922 / 紫 #bc8cff */
  --font-display: 'Space Grotesk', system-ui, sans-serif;
  --font-body: system-ui, -apple-system, 'Segoe UI', sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, 'Cascadia Code', monospace;
}
```

方向 B 把 `--bg` 提到 `#faf9f6`、文字 `#1a1a1a`、强调色用低饱和深色（墨绿 / 藏蓝 / 赭石）；方向 C 主色取项目 logo 或截图里已存在的颜色——**从素材提色永远好于凭空选色**。

**强调色选择**：优先从 logo / 截图 / banner 里取主色；取不到时按品类惯例（开发者工具蓝绿系、数据橙紫系、消费产品暖色系），避免默认紫 `#7c3aed` 系渐变——那是 AI 生成页最高频的识别特征。

## 2. 字体

- **来源**：Google Fonts 最多引 2 个 family（display + mono，正文用系统字体栈），`<link>` 加 `display=swap`，且 CSS 里永远写全 fallback——断网时页面不能塌
- **搭配**（三方向通用起步组合）：
  - A：Space Grotesk（display）+ 系统无衬线（正文）+ JetBrains Mono（代码/标签）
  - B：Newsreader 或 Source Serif 4（display）+ 系统无衬线（正文）
  - C：Outfit 或 Sora（display）+ 系统无衬线（正文）
- **层次**：hero h1 用 `clamp(2.5rem, 6vw, 4.5rem)`；h2 `clamp(1.75rem, 3.5vw, 2.5rem)`；正文 1rem–1.125rem、行高 1.6–1.7
- **纪律**：全页不超过 3 个 family；不用超过 2 种字重对比（如 700 vs 400）；标题不加 emoji；不整段用等宽字体（等宽只给代码、命令行、小标签）

## 3. 颜色

- **60-30-10**：60% 背景、30% 表面/次要文字、10% 强调色。强调色只做三件事：主 CTA、链接/hover、关键数据——满页都是强调色等于没有强调色
- **对比度**：正文对背景 ≥ 4.5:1，大标题 ≥ 3:1。方向 A 常见错误是 `--text-dim` 太暗（#8b949e 对 #0d1117 恰好及格，别再调低）
- **渐变**：至多一处（hero 背景或主按钮），至多两个色相且相邻（蓝→青可以，紫→橙不行）；不给文字上渐变
- **阴影**：方向 A/B 基本不用阴影，靠边框（1px `--border`）分层；方向 C 可用一层大半径柔和阴影，不要多层叠加
- **暗色双模式**（如选 `prefers-color-scheme`）：tokens 成对定义，强调色在暗色下提亮一档（蓝 #2563eb → #58a6ff），保证两种模式对比度都过线

## 4. 间距、圆角与阴影

- **间距体系**：4px 基数——组件内 8/12/16，组件间 24/32，章节间 `clamp(64px, 10vw, 128px)`。章节间距必须显著大于章节内间距，否则页面糊成一片
- **内容宽度**：正文列 `max-width: 72ch` 居中；通栏区块（hero、色带）满宽但内边距随视口 `clamp(16px, 5vw, 64px)`
- **圆角**：全页一个体系——卡片/按钮 8px、代码块 6px、图 12px，或统一 4px 走锐利风；忌混用（一个页面上 4/8/16/9999px 四种圆角是模板拼贴的信号）
- **卡片**：Features 用卡片时，同排卡片必须等高（grid + `align-items: stretch`）；卡片内不套卡片

## 5. Hero 区排版模式

从四种里按素材条件选一种，**选定一种做透，不混搭**：

| 模式 | 条件 | 布局 |
| --- | --- | --- |
| **左文右图** | 有 ≥1 张拿得出手的截图 | 左 55% 文案（h1 + tagline + CTA 行），右 45% 截图（加 1px 边框和微旋转 1–2° 增加生气） |
| **居中宣言** | 无截图但 tagline 有力 | 大 h1 + 副标题 + CTA 行 + 下方安装命令条；用背景细微纹理/单色渐变避免空洞 |
| **终端主角** | CLI 工具 | 上半文案，下半一个仿终端窗口（`<pre>` 静态输出即可，不必做打字动画），展示真实命令和输出 |
| **不对称拼贴** | 有 logo + 多张小图 | 大号 h1 偏左下，素材错落排布右上；方向 C 专用，做不好就退回左文右图 |

CTA 规则：主按钮一个（GitHub 仓库或"Get Started"），次按钮至多一个（文档/demo），幽灵样式；按钮行下方可放一行小字安装命令 + 复制按钮——让"想用的人"三秒内拿到命令。

## 6. 反 AI-slop 清单

生成后逐条过，命中任何一条就回去改。这些是"一眼 AI 生成"的高频特征：

- [ ] 紫色/靛蓝渐变居中大标题 + 下方三张等宽 feature 卡（最经典组合，出现即改布局或改色）
- [ ] 标题、按钮、卡片文字全部居中对齐（左对齐是默认，居中要理由）
- [ ] 每个 section 开头都是"Power your workflow with..."式空洞排比句
- [ ] emoji 当图标（用内联 SVG 图标或纯文字；没有合适图标就不放图标）
- [ ] 万金油形容词堆叠：seamless / cutting-edge / next-generation / blazing-fast 同时出现
- [ ] 三张卡片文案长度刻意对仗成排比（真实功能描述长短不齐是正常的）
- [ ] 假浏览器窗口 chrome + 里面放纯色块"截图"（没有真截图就换排版模式，不造假 UI）
- [ ] 页脚塞满不存在的链接（Community / Blog / Careers 之类仓库里根本没有的）
- [ ] 全站只有一种灰度、零个强调色，或反过来彩虹配色
- [ ] 所有圆角、间距、字号"看起来差不多"没有层次体系（回 §2/§4 定 tokens）

**一个正向判据**：把页面截图缩到指甲盖大小——如果还能认出"这个项目的主页"和"别的项目的主页"不一样（布局骨架或色彩有识别度），基本就过关了；如果缩略图像任何一个 SaaS 模板，重来。
