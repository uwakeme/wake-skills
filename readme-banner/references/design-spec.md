# README Banner 设计规范

> 这份文档是 `SKILL.md` 的补充。当 prompt 里的描述不够具体时，参考这里的数值。
> 大部分情况**不要**读这个文件——主 prompt 已经够用。只在用户对效果有更精细的要求时加载。

---

## 尺寸

| 用途 | 尺寸 (px) | viewBox | 比例 | 备注 |
|---|---|---|---|---|
| GitHub README 顶部 | 1280 × 320 | `0 0 1280 320` | 4:1 | **首选**，GitHub 渲染最稳 |
| GitHub README 顶部（高分辨率） | 1500 × 500 | `0 0 1500 500` | 3:1 | 适合需要更多细节的项目 |
| 个人 profile banner | 1500 × 500 | `0 0 1500 500` | 3:1 | GitHub profile 的「横幅」位 |
| 社交分享卡片 | 1200 × 630 | `0 0 1200 630` | 1.91:1 | 用于 OG image / Twitter card |

> **不要用** 16:9（1920×1080）当 README banner——会显得太扁，文字也难排。

---

## 字体

**永远用系统字体栈**，不要嵌字体（文件会爆）：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
             "Helvetica Neue", Arial, sans-serif;
```

| 角色 | 字号 | 字重 | 颜色对比度 |
|---|---|---|---|
| 主标题（项目名） | 56-72px | 700 (bold) | 与背景对比度 ≥ 7:1（AAA） |
| 副标题（tagline） | 20-24px | 400 (regular) | ≥ 4.5:1（AA） |
| 技术栈标签 | 14-16px | 500 (medium) | ≥ 4.5:1 |
| 角标（仓库 URL） | 12-14px | 400 | ≥ 3:1（次要信息允许） |

### 中英文混排注意

- 中文字号要比英文**略大**（同视觉大小，中文看起来更小）
- 标题用中文：字号 × 1.1
- 标题英文用 56-72px，中文用 64-80px

### 渐变（仅限「渐变彩色」风格）

**最多 2 个色 + 中间色**。推荐组合：

| 调性 | 起始色 | 终止色 |
|---|---|---|
| 科技蓝 | `#0d1117` | `#1f6feb` |
| 神秘紫 | `#1a0033` | `#7c3aed` |
| 极光绿 | `#0d1117` | `#3fb950` |
| 暖色夕阳 | `#1f2937` | `#f59e0b` |
| 冷色海洋 | `#0a1929` | `#06b6d4` |

> ❌ 不要用彩虹渐变（红橙黄绿蓝紫）——显廉价
> ❌ 不要用对比度过强的渐变（黑到白）——刺眼

## 构图：3 种推荐布局

### 1. 左对齐 + 右侧点缀（最常用）

```
┌────────────────────────────────────┐
│                                    │
│  Project Name                      │       ◯
│  Tagline goes here                 │      ╱ ╲
│                                    │
│                                    │
└────────────────────────────────────┘
```

- 文字距左 80px，垂直居中或 1/3 处
- 右侧 1/3 区域放装饰几何符号（圆、方块、线条）
- 适合 90% 场景

### 2. 居中对称（适合个人 profile）

```
┌────────────────────────────────────┐
│                                    │
│             Project Name           │
│           Tagline here             │
│                                    │
│      react • typescript • rust     │
│                                    │
└────────────────────────────────────┘
```

- 视觉重心最稳
- 适合技术含量高、要强调"专业感"的项目

### 3. 分栏（信息量大时用）

```
┌────────────────────────────────────┐
│                                    │
│  Project    │   tech stack         │
│  Name       │   ─────────          │
│             │   feature 1          │
│  Tagline    │   feature 2          │
│             │   feature 3          │
└────────────────────────────────────┘
```

- 适合 SDK / 工具类，要展示核心特性
- ❌ 不适合只是简单介绍的项目（信息会显得很挤）

## 装饰元素：克制清单

允许用（克制用，最多 1 个）：
- 圆 / 椭圆（最稳）
- 直线（分隔线）
- 简单的几何拼贴（几个方块旋转 45°）
- 同心圆 / 雷达环（适合 API / 网络相关项目）
- 极简坐标轴（适合数据 / 监控类项目）

**禁止用**：
- emoji
- 拟物图标
- 复杂插画
- 渐变填充的几何块（3D 感）
- 任何会让 banner 比项目本身还抢戏的元素

## 无障碍（必须做）

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1280 320" role="img">
  <title>Wake-Skills — 个人 Mavis skill 仓库</title>
  <desc>Wake-Skills 项目 README 顶部 banner，深色背景，左对齐项目名和副标题</desc>
  ...
</svg>
```

- `role="img"`：告诉屏幕阅读器这是个图
- `<title>`：必填，是 alt 文本
- `<desc>`：可选，提供更长描述
- 文字和背景的对比度要够（参考上面表格）
- 不要在 `<text>` 里塞屏幕阅读器读不出来的装饰字符

---

## GitHub 渲染的特殊坑

| 坑 | 症状 | 规避 |
|---|---|---|
| `<foreignObject>` | 整个 SVG 不渲染 | 不用 |
| `xlink:href` 外部引用 | 资源加载失败，图片空白 | 全部 inline |
| CSS 变量 `var(--...)` | 颜色 fallback 到黑色 | 用具体色值 |
| `<image>` 嵌 base64 | 文件爆，CDN 慢 | 别嵌图，纯矢量 |
| 超过 50KB | GitHub 渲染卡顿 | 压到 6KB 以下 |
| `transform-origin` 错 | 元素位置偏移 | 用绝对坐标，不要 transform 算相对位置 |
| `filter` 复杂效果 | Safari 渲染慢、Chrome OK | 避免复杂 filter，用纯色或简单渐变 |

## 反例：什么 banner 一定不要做

- **"全屏大 logo + 大标语 + 一堆装饰"** —— 这是 Instagram 头像，不是 README
- **"渐变彩虹 + 浮雕 + 阴影 + 玻璃拟态"** —— 这是 AI 默认输出，不专业
- **"科幻感线条 + 粒子 + 光效"** —— 这是游戏宣传图，不是开发者项目
- **"卡通吉祥物 + emoji 装饰"** —— 个人小项目才用，企业项目一律不要

> 检验标准：把 banner 缩到 200px 宽、放在 Google 搜索结果里。如果还能看清项目名 + tagline 通过、且不显廉价，就 OK。
