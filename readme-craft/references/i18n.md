# 多语言 README 规范

> readme-craft 的多语言支持参考。SKILL.md 主流程规定**何时多选**和**怎么写文件**，本文件规定**怎么翻译**和**每种语言该注意什么**。

## 1. 文件命名约定

GitHub 和大多数 Git 平台通过文件名后缀识别多语言 README：

| 文件名 | 用途 |
| --- | --- |
| `README.md` | 主 README，**永远是第一个选中的语言**（默认 English） |
| `README.zh-CN.md` | 简体中文（Simplified Chinese） |
| `README.zh-TW.md` | 繁體中文（Traditional Chinese） |
| `README.ja.md` | 日本語 |
| `README.ko.md` | 한국어 |
| `README.es.md` | Español |
| `README.fr.md` | Français |
| `README.de.md` | Deutsch |
| `README.pt-BR.md` | Português (Brasil) |
| `README.<bcp47>.md` | 其他 BCP-47 标签 |

**GitHub 自动展示规则**：访问者 locale 与某 README 匹配时，GitHub 会自动展示对应语言版本（用户在 `< > Code` 下拉里能看到）。所以**写对文件名后缀是关键**——即使 GitHub 没自动展示，用户也能手动选。

## 2. 翻译原则

### ✅ 必须翻译

- 所有 `##` `###` 标题
- 所有自然语言段落
- bullet 列表内容
- `> [!NOTE]` / `> [!TIP]` 等 Alerts 文字
- 表格中的描述列（不是 key 列）
- 代码块**外部**的注释（README 自己的注释）
- 项目名 tagline、Logo alt

### ❌ 不翻译

- shields.io 徽章 URL（`https://img.shields.io/...`）
- Markdown 链接 URL
- 文件名、目录名、命令、`code` 行内代码
- shields 徽章的 label/message（如 `[![License][license-shield]][license-url]` 中 label 还是 "License"）
- ASCII 树（项目结构）
- 技术术语、库名、框架名（MyBatis / Spring Boot / React 等保持英文）
- 标识符、变量名、class 名

### ⚠️ 视情况

- 代码块**内部**的注释 → 翻译（除非破坏代码可执行性）
- 表格的 key 列 → 不翻译
- 表格的 value 列 → 翻译

## 3. 每语言注意事项

### 简体中文 (zh-CN)

- **标点**：用全角标点（，。；：！？）；英文/数字前后保留**一个**空格
- **行末**：不留尾随空格（gfm-syntax 第 13 条）
- **段落**：中文段落间空一行
- **中英混排**：英文单词前后各加一个空格（`用 MyBatis 框架`，不是 `用MyBatis框架`）
- **章节标题**：可用 "关于" "快速开始" "使用示例" "许可证" 等
- **避免**：直译的 "步骤一" "步骤二"——可以简化或合并

### 繁體中文 (zh-TW)

- 用繁體字（"繁體" 不是 "繁体"）
- 標點用全形（，。；：！？）
- "軟件" 不寫 "软件"；"程式" 不寫 "程序"
- 技術術語保留英文（MyBatis / API 等）

### 日本語 (ja)

- 句読点是「、」「。」，**不是**「，」「。」
- 段落空行分隔；行末不留空格
- 漢字と仮名の混在OK；外来語カタカナ（`ライブラリ`、`フレームワーク`）可保留
- 長音符「ー」正确使用
- 見出し：「について」「はじめに」「使い方」「ライセンス」

### 한국어 (ko)

- 空格规范严格（한글 단어와 영어 단어之间必有空格）
- 句号 "。", 逗号 "，"
- 技术术语保留英文

### 拉丁语系（es / fr / de / pt-BR）

- 段落间距与英文一致
- 标题用 Sentence case（首字母大写即可，不全大写）
- 重音符号保留：Español / Français / Português
- 注意西语的倒置问号 `¿...?`

## 4. 跨语言一致性

每个语言版本必须满足：

| 要求 | 说明 |
| --- | --- |
| **章节顺序一致** | `## Features` 在 `## Installation` 之前，跨语言都一样 |
| **章节标题 key 一致** | 中英都用 `## Features`，不要中文写"功能特性"、英文写"Features"（影响交叉引用） |
| **shields 徽章数量一致** | 不要英文版 5 个、中文版 7 个 |
| **代码示例内容一致** | 不要中英版本用不同的命令或路径 |
| **结尾 License / Contributing 段都在** | 不因翻译而删 |

**章节标题要不要翻译？两种做法**：
- **方案 A（推荐）**：标题 key 不翻译，只翻译内容。例如中英文都用 `## Features` / `## 功能特性` 是错的——中英都用 `## Features` 才方便交叉引用。
- **方案 B**：标题完全翻译（`## 功能特性` / `## Features`）。优点是阅读自然，缺点是跨语言 anchor 不一致。

**选 A 更稳**。如果用户明确要"看起来像本地化的"，用 B。

## 5. shields 徽章跨语言处理

徽章 URL 不翻译，但 **label 可以本地化**（方案 B 风格）：

```markdown
<!-- 英文 -->
[![License](https://img.shields.io/badge/license-MIT-green)](./LICENSE)

<!-- 简体中文（同一 URL） -->
[![许可证](https://img.shields.io/badge/license-MIT-green)](./LICENSE)
```

不过这种**会让 shields 缓存命中率降低**（label 不同 = 不同 URL）。实际中**建议保持 label 英文**，仅在 README 正文里翻译。

## 6. 跨语言引用

**禁止**跨语言相互引用：
- ❌ 中文版写 "详细 API 见 [English README](#api)"
- ❌ 英文版写 "中文用户请看 README.zh-CN.md"

每个版本**自包含**。如果信息只在一个语言版本里，说明这个信息对其他语言受众不重要，可以不翻译。

**例外**：可以在每个 README 末尾加一行"其他语言版本"清单：

```markdown
## 其他语言

- [English](./README.md)
- [简体中文](./README.zh-CN.md)
- [日本語](./README.ja.md)
```

这行可以本地化（中文版叫"其他语言"，英文版叫"Other Languages"）。

## 7. 翻译质量自检 checklist

- [ ] 所有标题 key 一致（跨语言）
- [ ] shields URL 完全相同（不重新生成）
- [ ] 代码块完全相同（命令/路径不翻译）
- [ ] ASCII 树完全相同
- [ ] 技术术语保留英文（MyBatis / React 等）
- [ ] 段落数 ±10% 一致（不要中英版内容差距过大）
- [ ] 标点符合目标语言习惯（中文全角、日文「、」等）
- [ ] 行末无空格
- [ ] 段落用空行分隔
- [ ] 任何位置没有"待补充 / TBD"
